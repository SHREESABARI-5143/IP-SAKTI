# Contributing to AYURA (IP-SAKTI Sahayak)

Thank you for your interest in contributing to **AYURA (IP-SAKTI Sahayak)** — an open-source, source-cited AI and statutory classification intelligence engine built for the Ministry of Ayush, traditional medicine researchers, vaidyas, and Indian IP innovators.

---

## 🏛️ Code of Conduct

All contributors and participants are expected to adhere to our [Code of Conduct](CODE_OF_CONDUCT.md). Please treat all members of the community with respect and kindness.

---

## 🚀 How to Get Started

### 1. Fork & Clone
```bash
git clone https://github.com/SHREESABARI-5143/IP-SAKTI.git
cd IP-SAKTI
```

### 2. Backend Setup (FastAPI & Qdrant)
```bash
cd backend
python -m venv venv
source venv/bin/activate  # On Windows: .\venv\Scripts\Activate.ps1
pip install -r requirements.txt
cp .env.example .env
# Fill in your GEMINI_API_KEY in .env

# Run local Qdrant via Docker
docker run -p 6333:6333 -p 6334:6334 qdrant/qdrant

# Ingest and index the legal corpus
python scripts/embed_and_index_qdrant.py

# Start Backend Server
uvicorn app.main:app --host 0.0.0.0 --port 8000 --reload
```

### 3. Frontend Setup (Next.js 15)
```bash
cd ../frontend
npm install
npm run dev
```
Open [http://localhost:3000](http://localhost:3000) to view the UI.

## 🌿 Contribution Guidelines

1. **Statutory Integrity**: We strictly adhere to **zero mock data** for legal text. Any addition to the legal corpus (`data/`) must be verified against actual Gazettes of India or official pharmacopoeias (API/AFI).
2. **Citation Rule**: All RAG answers generated by AI must feature strict inline bracketed citations (e.g. `[Source: Patents Act 1970, Section 3(p)]`).
3. **Multilingual Standards**: Support for the 7 official Indian languages (EN, HI, SA, TA, TE, MR, BN) must preserve correct Devanagari / Indic script rendering.
4. **Branching Strategy**:
   - `main`: Production-ready code.
   - `feat/feature-name` or `fix/issue-name` for your pull requests.

---

## 📬 Pull Request Process

1. Create a descriptive branch from `main`.
2. Ensure your changes pass linting and build checks without warnings.
3. Open a Pull Request referencing any open issue numbers.
4. Maintainers will review your PR for statutory accuracy, security, and UI elegance.
